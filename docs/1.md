## Architecture Summary

This project is a **FastAPI-based task execution framework**. Its design philosophy:

- **Tasks are standalone Python files** placed in `tasks/<flow>/<task>.py`, each exporting a `run(data)` function. No registration, no decorators -- just drop a file in the right place.
- **API layer** (`app/api/`) provides two endpoints: one to discover available tasks by scanning the filesystem, and one to execute any discovered task by flow/task name.
- **Core services** handle configuration (from `.env`), logging (JSON to daily-rotated files), dynamic module loading (via `importlib` with caching), and SMTP email notifications on task failure.
- **Pydantic schemas** validate and sanitize user input (flow/task names are restricted to safe patterns and auto-lowercased to prevent path traversal).
- **Windows service support** is provided via NSSM scripts for production deployment on Windows

### 1. 高优先级

**1.1 `task.py` Line 79 — 失败路径下 `duration_ms` 重复计算**

```python
# 异常分支内（line 69）
duration_ms = int((time.perf_counter() - start_time) * 1000)  # 第一次计算

# try/except 外部（line 79）
duration_ms = int((time.perf_counter() - start_time) * 1000)   # 第二次覆盖，值相同
```

失败路径上计算了两次（值相同，但冗余）。建议将 line 79 移入 `else` 分支或统一提取到 `finally`。

**1.2 `task.py` Line 67 — `traceback.format_exc()` 已包含异常信息，`str(e)` 冗余**

```python
error_message = traceback.format_exc() + "\nError: " + str(e)
```

`traceback.format_exc()` 输出的最后一行就是异常类型和消息，额外拼接 `str(e)` 会导致错误信息重复出现。

**1.3 `task.py` GET `/task/list` — 每次请求都做全文件系统扫描 + 两次 `sorted()`**

[task.py](file:///d:/Project/Github/fastapi-task/app/api/task.py#L30-L42) 使用嵌套列表推导式，每次请求都会 `iterdir()` 遍历所有子目录和 `.py` 文件，并且有两次 `sorted()` 调用（目录 + 文件）。高并发下会产生不必要的 I/O。建议：
- 添加缓存（如 `lru_cache` + TTL），仅在任务文件变化时刷新
- 或将 `sorted()` 合并为一次

**1.4 `email.py` Lines 57-63 — 附件整体读入内存**

```python
with open(file_path, "rb") as f:
    part = MIMEApplication(f.read(), Name=os.path.basename(file_path))
```

大附件会导致内存溢出。建议对附件大小做限制，或改用流式方式读取。

**1.5 缺少任务执行超时控制**

`asyncio.to_thread(task_run_func, request.data)` 没有超时限制，一个死循环或长时间运行的任务会永久占用线程。建议使用 `asyncio.wait_for` 包装，设置超时时间。
